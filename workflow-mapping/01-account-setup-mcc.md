# 01 开户与账户结构（MCC 规划）

**目标**：用一套 MCC 架构支撑多账号、多市场、多产品线的投放，避免后期因结构混乱导致权限失控、转化口径分裂、账单扯皮。

**一句话结论**：MCC 是管理容器，不是投放容器——投放隔离靠子账号，能力共享靠显式配置，没有"自动继承"。

## 前置条件

- 确定结算主体：每个子账号独立结算（币种、时区、账单资料一旦创建不可更改）
- 确定投放主体划分维度：按市场（HK / 海外）、按产品（App A / App B）、按职能（拉新 / 再营销）三选一为主维度
- 准备好各子账号的域名归属证明（金融行业后续验证要用）

## 步骤

### 1. MCC 层级规划

- 一个公司主体原则上一个 MCC；代理商代投用独立 MCC 或被邀为子账号管理员，避免产权纠纷
- 子账号命名规范：`{市场}_{产品}_{职能}_{币种}`，例如 `HK_XWallet_UA_HKD`。命名是给半年后的自己看的
- MCC 内用户权限按最小必要分配：Admin（可改结构）/ Standard / Read only / Email only 四档；离职即清退

### 2. 子账号划分逻辑

- **按市场划分**：不同市场 = 不同语言、时区、币种、合规要求，必须分账号
- **按产品划分**：不同 App = 不同转化事件、不同 SDK，不能混在一个账号里出价
- **按职能划分**：拉新（ACi）与再营销（ACe）可同账号不同系列；只有当预算/团队完全独立时才分账号
- 反模式：按"渠道"分账号（一个账号跑 Google、一个跑 Meta 没有意义，MCC 不跨平台）

### 3. 系列架构（子账号内）

- 一个优化目标 = 一个系列。不要把 install 和 in-app action 塞进同一个系列
- iOS 与 Android 分系列（归因机制、CPI、出价完全不同）
- 命名规范：`{平台}_{目标}_{出价}_{日期}`，例如 `UAC_iOS_newApply_tCPA_0923`
- 广告组按素材主题划分（UGC / 产品录屏 / 促销），不要按受众切太碎——UAC 本来就没有精细定向

### 4. 能力共享的显式配置（MCC 不会自动给你）

- 跨账号转化跟踪：需在 MCC 层设置，子账号选择使用 manager account 的 conversion action
- 受众共享：需开启 manager account 的 continuous audience sharing，且名单符合政策资格
- 否定关键词/展示位置排除列表：MCC 层可建共享列表，再逐个关联到系列
- 账单：MCC 层可设统一账单（manager account 承担），但需要显式配置

## 检查点

- [ ] 每个子账号的时区、币种、结算主体确认无误（不可改）
- [ ] 命名规范文档化，新人可执行
- [ ] MCC 用户清单每季度清理一次（离职、换岗）
- [ ] 跨账号共享的每一项都有明确的"谁开了、开给谁"记录

## 常见坑

- **一个账号里塞多个 App**：转化事件打架，出价模型学歪，拆分时代价巨大
- **MCC 权限给太大**：代理商拿了 Admin 权限，解约时交接噩梦
- **以为 MCC 下默认共享转化/受众**：全部需要显式开启，默认是隔离的
- **时区币种建错**：只能重建账号，历史数据无法迁移
